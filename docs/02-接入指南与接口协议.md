# 公共库接入指南与接口协议

更新时间：2026-09-08 16:24 +0800

版本：v2.0 · 公共库设计规范。以下包和方法是待实现契约，不是当前已发布 API。

## 1. 接入步骤

1. 前端安装 React 查看包与 core 包，把 FilePreview 放到原有页面。
2. Go 或 Node.js 后端引入对应集成库，传入已有数据库连接和派生结果存储适配器。
3. 实现“读取登录身份”“判断附件权限”“定位并读取原文件”三个项目适配点。
4. 把库的 HTTP handler 挂在项目自己的 `/api/file-preview/v1` 下，经过已有登录与写请求防伪造中间件。
5. 在项目发布流程显式执行库提供的 SQL 升级，再启动引用同一个后端库的后台处理进程。
6. 配置转换镜像和前端静态资源；把业务文件删除事件接到库的源失效方法。

项目已有上传、下载和登录接口继续承担原职责。组件接收业务文件引用，不要求用户再向预览功能上传一次。

## 2. React 页面接入

拟定包名为 `@unipat/file-preview-react`、`@unipat/file-preview-core`。正式发布后用项目包管理器安装锁定版本；示例中不列当前可执行的安装命令，避免误装其他同名包。

```tsx
import { useMemo } from 'react';
import { FilePreview } from '@unipat/file-preview-react';
import { createHttpPreviewClient } from '@unipat/file-preview-core';
import '@unipat/file-preview-react/styles.css';

// appRequest：项目已有的请求封装，返回原生 Response；包含登录续期与写请求 CSRF 头。
// authCacheKey：项目、租户、用户或登录会话变更时必定改变的非秘密缓存标识。
export function AttachmentPreview({ attachment, authCacheKey, appRequest, downloadAttachment }) {
  const client = useMemo(() => createHttpPreviewClient({
    baseUrl: '/api/file-preview/v1',
    request: appRequest,
  }), [appRequest, authCacheKey]);

  return <FilePreview
    client={client}
    identityKey={authCacheKey}
    file={{ resourceKey: attachment.id, version: attachment.version }}
    profileId="standard-v1"
    assetsBaseUrl="/assets/file-preview/0.1.0/"
    height={720}
    locale="zh-CN"
    onDownload={() => downloadAttachment(attachment.id, attachment.version)}
    onError={(error) => reportPreviewError(error.code, error.requestId)}
  />;
}
```

示例中的 attachment、appRequest、下载函数和错误上报由项目提供。`identityKey` 只负责隔离浏览器缓存，不作为服务端身份凭据。组件不访问项目的全局 token、localStorage、路由器或消息弹窗。

### 2.1 组件接口

| 属性 | 类型与默认值 | 行为 |
|---|---|---|
| `file` | `{resourceKey:string, version:string}`，必填 | 文件引用；任一变化取消旧请求并重新加载 |
| `client` | PreviewClient，必填 | 可使用标准 HTTP 客户端，也可由项目自行适配接口 |
| `identityKey` | string，必填 | 登录或租户变化时清空缓存，阻止迟到响应写入新界面 |
| `profileId` | string，必填 | 后端已登记的不可变处理规则 |
| `assetsBaseUrl` | string，必填 | 本项目托管的 PDF Worker、字体等静态资源根路径 |
| `height` | number 或 CSS 长度，默认 640px | 组件容器高度；宽度默认占父容器 |
| `locale` | 默认 zh-CN | 文案由库管理，可传受控翻译表覆盖 |
| `cspNonce` | 可选 string，来自项目当前页面的 CSP nonce | 仅用于库创建的受控样式节点，禁止下发给源文件脚本 |
| `theme` | 可选颜色、字体、圆角变量 | 只作用于组件容器，不写全局 body 样式 |
| `onReady` | `(info) => void` | 首份内容可见，包含 previewId、publishedRevision、availability |
| `onStatusChange` | `(status) => void` | 状态或实际进度变化时触发 |
| `onError` | `(error) => void` | 包含 code、message、retryable、requestId，无文件正文 |
| `onDownload` | 可选回调 | 仅当后端允许下载且提供此回调时显示“下载原文件” |

重试按钮调用 client.retry，后端再次校验权限；清理结果等管理功能不出现在普通阅读工具栏。打印仅针对存在 PDF 的结果且权限允许时显示；复制权限控制组件交互，不是防截图或防浏览器读取保证。

### 2.2 自定义请求客户端

```ts
interface FileRef { resourceKey: string; version: string }
interface RequestOptions { signal?: AbortSignal }
interface PreviewClient {
  ensure(file: FileRef, profileId: string, options?: RequestOptions): Promise<PreviewState>;
  getState(previewId: string, options?: RequestOptions): Promise<PreviewState>;
  getManifest(previewId: string, revision: number, options?: RequestOptions): Promise<Manifest>;
  readArtifact(artifactId: string, options?: RequestOptions & {
    range?: { start: number; endInclusive?: number }
  }): Promise<Response>;
  readSheetRange(previewId: string, query: SheetRange, options?: RequestOptions): Promise<SheetWindow>;
  retry(previewId: string, options?: RequestOptions): Promise<PreviewState>;
}
```

PreviewState、Manifest、SheetRange 和 SheetWindow 由 core 包从协议定义生成。浏览器 API 使用 camelCase，标准 HTTP 序列化统一为本章的 snake_case；映射由 core 完成，项目不自行改字段含义。资源编号和版本区分大小写；resourceKey 最长 256 字符，version 最长 128 字符。

请求封装必须支持 AbortSignal，不能把 JSON 包装后的错误页当作文件 Response。遇到登录失效，由项目请求层刷新登录并至多重放一次幂等请求；仍失败返回组件的 AUTH_REQUIRED 状态。组件不创建另一套查看会话、启动码或用户令牌。

## 3. Node.js 后端接入

```ts
import { createPreviewHost, mysqlStore } from '@unipat/file-preview-node';

const preview = createPreviewHost({
  namespace: 'project-a',
  store: mysqlStore({ pool: existingMysqlPool, tablePrefix: 'preview_' }),
  source: projectFileSource,
  artifacts: projectPreviewStorage,
  authorize: authorizeProjectAttachment,
  runner: isolatedConverterRunner,
  profiles: [standardProfile],
});

app.use('/api/file-preview/v1',
  requireLogin,
  csrfForStateChangingRequests,
  preview.expressHandler({
    getPrincipal: req => ({
      tenantId: req.auth.tenantId,
      userId: req.auth.userId,
      authContext: req.auth.previewAuthContext,
    }),
  })
);
```

上述变量均由项目显式传入。Node 的 mysqlStore 接受项目已有 mysql2 Promise Pool；不修改其连接池大小、不调用 end 关闭项目连接。若项目使用 ORM，可传入同一数据库的独立受限连接池，或实现本规范的 Store 适配器。请求处理不等待转换完成。

后台单独入口引用同一配置工厂并启动 `preview.createWorker({workerId, concurrency:2}).run(signal)`；进程退出前先停止领取，再有界等待或取消已领取任务。配置工厂可以复用，API 实例与后台进程不能误以为共享进程内任务队列。

数据库升级由发布入口调用 `preview.migrate({targetVersion})`，不在 import、构造对象或处理请求时执行。权限不足或 schema 版本不匹配时 readiness 失败，指出需要的版本。

## 4. Go 后端接入

Go module 暂以 `<module>/host-go` 表示真实发布地址，正式文档由发布配置替换。Go 接入与 Node.js 使用相同数据库规范及 HTTP 协议。

```go
// 示意代码；previewhost、mysqlstore 是拟定模块导入别名。
host, err := previewhost.New(previewhost.Config{
    Namespace: "project-a",
    Store: mysqlstore.New(existingSQLDB, mysqlstore.Options{TablePrefix: "preview_"}),
    Source: projectFileSource,
    Artifacts: projectPreviewStorage,
    Authorize: authorizeProjectAttachment,
    Runner: isolatedConverterRunner,
    Profiles: []previewhost.Profile{standardProfile},
})
if err != nil { return err }

handler := host.HTTPHandler(previewhost.HTTPOptions{
    Principal: principalFromProjectRequest,
})
// mountProjectRoute 表示项目的路由注册；内部应用已有登录、CSRF 中间件，
// 并在转交 handler 前移除 /api/file-preview/v1 前缀。
mountProjectRoute("/api/file-preview/v1", handler)
```

Go 的默认 Store 接受 `*sql.DB`。若项目使用 GORM，通过已有连接取得底层 `*sql.DB`，由库在自己的事务里操作 preview_ 表，不接管项目连接池。Gin 接入用 WrapH 挂载标准 handler，项目负责把可信 principal 放入标准请求上下文。

后台入口调用 `host.NewWorker(options).Run(ctx)`，采用与 API 相同的 namespace、Store 和 profile。Node 与 Go 都由包负责领取与发布规则，项目不自行写一套“定时扫表修改状态”的代码。

## 5. 项目必须实现的适配器

### 5.1 身份与权限

```ts
type PreviewAction = 'view' | 'generate' | 'retry' | 'cancel' | 'clear';
interface Principal {
  tenantId: string; userId: string;
  authContext?: Readonly<Record<string, unknown>>; // 项目可信登录上下文，例如会话编号和到期时间
}
interface AccessDecision {
  allowed: boolean;
  permissions?: { downloadOriginal: boolean; print: boolean; copy: boolean; retry: boolean };
}
type Authorize = (input: {
  principal: Principal; file: FileRef; action: PreviewAction; signal: AbortSignal;
}) => Promise<AccessDecision>;
```

库的 namespace 来自后端配置，principal 来自项目已验证的登录上下文。authorize 必填；需要验证登录会话撤销或到期的项目，通过 authContext 提供可信上下文供回调重复检查。authContext 不写清单、任务或日志。回调异常时拒绝访问，不提供默认放行实现。项目在这里核对租户、业务对象、文件版本和当前角色；库不接受浏览器提交的 owner、role 或 tenant_id 作为权限依据。

创建接口先要求 view；首次需要生成时还要求 generate。状态、清单、每个分块和产物读取都检查 view。retry、cancel、clear 分别检查相应操作。权限返回的下载和复制等标志用于页面呈现，原文件下载仍由项目已有下载接口再次检查权限。

`401` 表示需要项目登录；`403` 表示用户已登录但不允许执行该操作。无权知道其存在的文件统一 `404 RESOURCE_NOT_FOUND`。登录变化后，项目必须改变组件 identityKey，避免复用上一用户的数据缓存。

### 5.2 原文件定位与读取

```ts
interface ResolvedSource {
  resourceKey: string;
  version: string;
  filename: string;
  extension: string;
  sizeBytes: number;
  expectedSha256?: string;
  handle: Record<string, unknown>; // 项目适配器的内部句柄，不返回浏览器
}
interface SourceProvider {
  resolve(scope: {namespace: string; tenantId: string}, file: FileRef,
          signal: AbortSignal): Promise<ResolvedSource>;
  open(source: ResolvedSource, options: {
    signal: AbortSignal;
    range?: {start: number; endInclusive: number};
  }): Promise<{stream: ReadableStream<Uint8Array>; sizeBytes: number; version: string}>;
  isAvailable(source: ResolvedSource, signal: AbortSignal): Promise<boolean>;
}
```

这是跨语言概念接口；Go 对应 context、结构体和 io.ReadCloser，不要求 Go 使用 Web Stream。Node 的标准封装可适配 Node Readable 与 Web Stream。读取句柄可以保存项目存储的对象 key 和 versionId，不能保存预签名 URL、用户访问令牌或存储密钥。

浏览器只提交 resourceKey 和 version。resolve 在权限通过后执行，并校验源属于当前租户。open 必须读取指定不可变版本，返回的 version 与登记一致，服务再核对长度和实际 SHA-256。声称同版本却返回其他字节时，标记 SOURCE_CHANGED，不发布结果。

如果项目仅有一个会被覆盖的文件路径，适配器必须先制作不可变副本，再把副本版本登记给库。副本仍放在项目存储中，由项目管理。公共库可以提供流式 snapshot 工具辅助复制，但不能用文件名或修改时间代替版本保证。原文件生命周期归项目所有。

### 5.3 派生结果存储

```text
stat(key) -> sizeBytes, sha256, mediaType
openRange(key, start, endInclusive, signal) -> stream
put(key, stream, expectedSize, expectedSha256, signal) -> metadata
delete(key) -> success
list(prefix, cursor) -> objects, nextCursor
```

只允许操作配置的派生结果前缀，例如 `preview-results/project-a/`。提供 Local 和 OSS 标准适配器，接入方可对自己的存储 SDK 做薄封装。普通结果删除不能越过此前缀，也不能沿 source handle 删除原文件。

### 5.4 转换运行器

```text
run(jobInput, readOnlySource, outputDirectory, limits, cancellation) -> CandidateResult
cancel(jobId) -> acknowledged
capabilities() -> protocolVersions, imageDigest, fontDigest, supportedFormats
```

标准运行器为受限容器；项目负责配置可用的容器环境。库控制启动、超时、结束和结果验证。运行器不接受浏览器传来的命令、镜像地址或任意宿主机挂载。转换输入输出协议详见 03，资源边界详见 04。

## 6. 标准 HTTP 接口

默认前缀 `/api/file-preview/v1`，项目可统一调整。所有接口由项目身份中间件保护；库不要求项目创建另一套 API key。JSON 成功响应为 `{request_id,data}`，错误为 `{request_id,error:{code,message,retryable,details}}`。所有时间使用 UTC RFC 3339，字节数使用整数。

| 方法及相对路径 | 请求 | 响应与规则 |
|---|---|---|
| `POST /previews` | file_ref、profile_id | 202 新建或活动任务；200 已有终态记录；重复调用不自动重试失败任务 |
| `GET /previews/{id}` | 无 | 200 状态、权限及当前发布版本；不创建任务 |
| `GET /previews/{id}/manifest` | published_revision 必填 | 固定发布版本清单；无结果 409 |
| `GET /artifacts/{id}/content` | 可带 Range；HEAD 同路径 | 当前用户有 view 权限后返回字节流 |
| `GET /previews/{id}/sheets/{sheet_id}/range` | published_revision、row_start、row_end、col_start、col_end | 一次最多 200 行 × 100 列，坐标从 1 开始且包含末端 |
| `POST /previews/{id}/retries` | 可选 reason，仅允许枚举 user_requested | 202 新一轮生成；已有活动任务 409 ALREADY_RUNNING |
| `POST /previews/{id}/cancel` | 无 | 200 取消当前轮次，保留已发布结果；重复请求不改变终态 |
| `DELETE /previews/{id}/results` | 无 | 202 清理库内结果并取消当前轮次；不删除原文件 |

源失效通知是后端库的内部方法，不默认暴露给浏览器。原文件上传和下载使用项目已有接口，不在本库再定义一套重复接口。

```http
POST /api/file-preview/v1/previews
Content-Type: application/json
Idempotency-Key: attachment-123-v2-standard-v1
X-CSRF-Token: <由项目请求层提供，具体名称遵循项目约定>

{"file_ref":{"resource_key":"attachment-123","version":"v2"},"profile_id":"standard-v1"}
```

```json
{
  "request_id":"req_01",
  "data":{
    "preview_id":"prv_01",
    "file_ref":{"resource_key":"attachment-123","version":"v2"},
    "profile_id":"standard-v1",
    "generation":1,
    "execution_state":"queued",
    "availability":"none",
    "stage":"queued",
    "progress":null,
    "revision":1,
    "published_revision":null,
    "is_previous_result":false,
    "permissions":{"download_original":true,"print":true,"copy":true,"retry":true},
    "warnings":[],
    "error":null,
    "retry_after_ms":2000
  }
}
```

用户权限由每次请求实时获得，不保存在共享的转换清单里。权限变化时状态查询返回新的权限；状态 ETag 同时包括预览 revision 和当前权限摘要，不能在权限变化后误返回 304。

## 7. 重复请求、取消与重试

POST 创建与重试必须携带 16–128 字符 Idempotency-Key。幂等范围为 namespace、tenant_id、user_id、方法、规范化路由和键，记录保留 24 小时。同键同内容返回同一预览操作结果，同键不同内容 409 IDEMPOTENCY_CONFLICT；操作仍提交中返回 409 REQUEST_IN_PROGRESS。

每次重放仍检查当前用户权限，并用当前状态重新包装响应。幂等记录只保存操作编号和稳定结果，不保存旧的 permissions 或用户令牌。不同用户同时请求同一源版本还通过数据库唯一键合并为一条预览。

客户端轮询从 2 秒逐步延长至 10 秒并增加随机偏移，遵守 Retry-After；页面不可见时暂停高频请求。查询不创建转换。文件变化、身份变化、组件卸载都取消请求，迟到响应必须匹配 identityKey、文件引用和 published_revision。

人工重试创建新 generation，并使用新的 job 目录。已有结果在生成期间继续提供，is_previous_result=true；失败后仍能看旧结果。取消只停止当前轮次，不撤回已经发布的内容；清理结果使用 DELETE results。

## 8. 原文件失效与结果清理

项目删除业务附件或废弃某个版本时，在同一个业务数据库事务中写入持久化待通知事件；事务提交后调用 `preview.invalidateSource(scope, fileRef, reason)`。失败事件重试直到库确认，不能只发送进程内事件或依赖浏览器通知。

库收到通知后将源记录标为 unavailable，取消其全部活动任务，阻断结果访问并清理派生对象。项目权限函数在业务删除生效后也应立即拒绝查看，使通知短暂延迟期间仍不能读取已删除附件。

普通缓存清理 `DELETE results` 不把业务源标成不可用。清理期间返回 CLEAR_IN_PROGRESS；完成后旧预览记录保持 cancelled/none，具有 retry 权限的用户可以显式重新生成。清理旧对象不能删除后续新 job 的产物。

## 9. 文件内容读取

所有内容通过项目请求客户端读取：PDF.js 适配器使用请求层处理授权与 Range；图片 fetch 后使用 Blob URL；文本和表格读取 JSON/文本；HTML fetch 后注入空 sandbox 的 srcdoc。组件不把用户 token 拼到内容 URL，也不要求 Cookie 一定能由原生 iframe 自动携带。

内容响应只允许协议登记的 MIME，禁止把未清理的源 HTML 当作可执行页面返回。HTML 产物接口使用 text/plain 或附件响应，由组件读成字符串后进行受限展示。源文件普通下载由项目自己提供。

Range 支持单一连续范围 `bytes=0-999`、`bytes=1000-`、`bytes=-500`。先按实际长度 N 归一化；有效范围 206，返回 Content-Range、实际 Content-Length 和 Accept-Ranges。越界 416，Content-Range 为 bytes */N；多区间按 HTTP 允许方式忽略 Range 返回完整 200；语法错误 400。HEAD 返回一致的元数据，无响应体。

产物 ETag 使用加引号的 SHA-256；If-Range 仅接受该强 ETag，匹配时读取范围，不匹配返回完整内容。先验证权限再判断条件请求，避免泄露其他租户的文件长度和摘要。内容关闭动态压缩，防止 Range 针对的字节与传输不一致。

动态内容默认 Cache-Control: no-store；前端仅保留有界内存缓存。长传输每秒重新检查源有效性与项目权限，检查失败中止后续发送。已经发送给浏览器的内容不能远程收回；退出登录时项目卸载组件或改变 identityKey。

## 10. 常见错误与组件表现

| code | HTTP | 处理 |
|---|---|---|
| AUTH_REQUIRED | 401 | 交给项目登录流程，停止继续读内容 |
| RESOURCE_NOT_FOUND | 404 | 文件不存在或无权知道其存在 |
| ACTION_FORBIDDEN | 403 | 隐藏或禁用相应操作，不能前端绕过 |
| SOURCE_UNAVAILABLE / SOURCE_CHANGED | 410 / 409 | 停止读取，业务后端核对文件版本；不会换成最新文件继续显示 |
| PREVIEW_NOT_READY | 409 | 展示排队或运行状态，继续有界轮询 |
| ALREADY_RUNNING | 409 | 查询现有任务 |
| CLEAR_IN_PROGRESS | 409 | 等待清理完成后才能重新生成 |
| RESULT_EXPIRED | 410 | 清空旧缓存，重新读取当前清单 |
| SHEET_RANGE_NOT_SATISFIABLE | 416 | 修正行列范围 |
| WINDOW_READ_LIMIT | 422 | 缩小表格窗口 |
