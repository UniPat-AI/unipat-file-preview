# 包组织、静态资源与发布规范

更新时间：2026-09-08 16:24 +0800

版本：v2.0 · 公共库设计规范。包名和导出方法为设计契约，未发布。

## 1. 仓库组织

```text
unipat-file-preview/
  docs/
  contracts/                 # 清单、接口、错误码、28 种格式的唯一规范
  packages/
    core/                    # @unipat/file-preview-core
    react/                   # @unipat/file-preview-react
    node/                    # @unipat/file-preview-node
  host-go/                   # Go module，与 Node 后端契约一致
  database/mysql/            # 两种后端共同打包的 SQL 升级与查询模板
  converter/                 # Python 处理器、格式化辅助程序、容器与字体清单
  fixtures/                  # 去除敏感信息的格式样本和预期结果
  conformance/               # 跨后端的同一套行为验收
  examples/
    react-node/
    react-go/
```

这些目录为实现时的组织规范；本次仓库交付仍为 docs。每个包有明确入口，前端构建不通过导入 core 意外打包 Node、数据库驱动、文件系统模块或转换镜像。

## 2. NPM 包边界

### 2.1 core

core 导出 FileRef、PreviewState、Manifest、PreviewClient、createHttpPreviewClient、错误码和格式查询方法。它负责请求排队、取消、状态规范化和固定发布版本读取，不依赖 React，不控制项目的路由或登录界面。

HTTP 客户端接受项目 request 函数。内容读取默认最多 4 个并行请求，取消文件会取消其排队请求；请求缓存键必须包含身份、源版本、发布版本和数据窗口。缓存属于组件控制器或明确创建的客户端实例，不把用户数据存在全局单例里。

顶层 import 不访问 window、document、localStorage，不启动定时器、不进行网络请求，使服务端渲染阶段能够安全解析模块。实际浏览器加载和轮询由组件挂载时显式创建。

### 2.2 react

react 包导出 FilePreview、必要类型和 styles.css。React 与 ReactDOM 使用 peerDependencies，由项目提供同一份 React；本设计的直接兼容范围为 React 19，与当前 GDPVal 一致，不在未经验证时宣称所有 React 主版本可用。

库内部的 PDF.js 和 Univer 适配器通过动态 import 按格式加载。打开 TXT 不加载表格引擎，打开图片不初始化 PDF Worker。打包配置保留动态模块边界，不能在一个统一 index 中同步导入所有查看器。

样式限定在 `.gfp-root` 下，不修改全局 body、button、table；弹层挂到组件提供的容器。Univer 的依赖样式需要打包时做范围限制，并验证项目已有表格实例不会相互污染。主题通过明确的 CSS 变量和 prop 传入，不依赖项目必须安装 Ant Design 或使用某个全局主题状态。

发布 package.json 的主要字段示例如下，真实版本由发布流程写入：

```json
{
  "name":"@unipat/file-preview-react",
  "version":"0.1.0",
  "type":"module",
  "files":["dist","assets","bin"],
  "exports":{
    ".":{"types":"./dist/index.d.ts","import":"./dist/index.js"},
    "./styles.css":"./dist/styles.css",
    "./assets.json":"./assets/manifest.json"
  },
  "types":"./dist/index.d.ts",
  "sideEffects":["**/*.css"],
  "peerDependencies":{"react":"^19.0.0","react-dom":"^19.0.0"},
  "bin":{"file-preview-assets":"./bin/assets.js"}
}
```

示例省略具体运行依赖，正式发布必须包含经过验证的锁定依赖关系。files 控制发布内容、peerDependencies 表达宿主依赖，依据 [NPM package.json 官方说明](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/)。此处使用 ESM；不提供未测试的 CommonJS 入口。

### 2.3 Node 后端包

node 包仅供服务端使用，导出 createPreviewHost、mysqlStore、标准存储适配器、Runner 接口和 HTTP 适配器。Express 通过显式 expressHandler 接入，核心业务逻辑不依赖 Express。包构造时只校验配置，不监听端口、不执行 SQL 升级、不启动工作循环。

Node 后端运行支持在仍维护的 Node.js LTS 版本上验证，具体最低版本写入发布包 engines 和兼容矩阵；不把模糊“支持 Node”替代运行验证。生产镜像固定实际 Node 版本和包锁文件。

数据库、对象存储与日志连接由项目持有。库创建的事务和文件流由库释放；项目传入的池、存储客户端和服务器由项目关闭。shutdown 方法只停止库自己的工作任务及缓存。

## 3. Go module

host-go 核心包使用 context 与标准 HTTP 接口，不绑定 Gin 或某个业务 ORM。mysqlstore 使用底层 SQL 连接，存储适配器采用流式 io 接口。Go 项目按版本引用 module，并将工作进程与 API 进程构建为项目自己的产物。

SQL 模板和 schema 文件在 Go 构建时嵌入，同时原样打包进 Node 包。生成后的协议类型分别检查；两个后端不能手工维护不同版本的错误码和字段表。

module 不在 init 中创建连接、启动 goroutine 或注册项目路由。项目显式 New、挂 handler、执行 schema 升级、Run worker。Run(ctx) 取消时停止领取，等待或取消自己的子任务，不调用全局进程退出。

## 4. 静态资源如何随包接入

PDF Worker、CMap、字体、WASM 及查看器必要图片随包发布，所有浏览器资源由接入项目托管，不默认指向第三方 CDN。assets/manifest.json 记录每个文件的相对路径、SHA-256、兼容组件版本和引擎版本。

项目构建阶段执行包提供的显式资源复制命令，将资源复制到例如 `/assets/file-preview/0.1.0/`，再把相同地址传给组件。CLI 只写用户指定的输出目录，不修改路由和环境配置；同名文件摘要不一致时停止，要求使用新的版本目录。

组件构造 PDF Worker 时使用当前实例的资源地址和匹配引擎，不改写项目其他 PDF.js 实例的全局 Worker 配置。卸载时销毁库创建的 Worker。多个实例若共享资源，只共享静态文件或有引用计数的工作池，不共享文件权限或用户数据。

发布构建验证资源路径能在站点子路径、带 hash 文件名、CDN 前缀以及浏览器 Worker 环境下正确解析。找不到资源返回 STATIC_ASSET_MISSING，版本不符返回 STATIC_ASSET_VERSION_MISMATCH，不能只在控制台出现空白。

PDF.js 参数与 Worker 能力按照 [官方 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html)适配。主 JS 与 Worker 来自同一引擎版本，不允许各自独立自动更新。

## 5. HTML 内容隔离与宿主 CSP

公共组件直接进入业务页面，文件 HTML 只能进入单独的空 sandbox iframe。内容由已鉴权的 request 读取，服务返回 text/plain 的清理后产物；组件重新检查允许的静态结构，再组装受控 srcdoc。源文件不能进入组件根节点的 innerHTML。

srcdoc 先放库控制的 CSP meta，再放经过清理的静态内容；空 sandbox 禁止脚本、同源、表单、弹窗和下载。文件内提供的 meta、base 和自定义 CSP 全部移除。浏览器沙箱及 srcdoc 的行为依据 [MDN iframe 说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)。

宿主页面的 CSP 会约束内层展示。组件不要求项目放宽全站脚本策略，不使用 eval 或远程脚本。图片 Blob、内嵌图片 data 和 Worker 资源所需来源由项目显式登记。若宿主禁止文件内样式，显示可读结构并提示样式受限，不静默关掉 sandbox 或把不可信 HTML 放回业务 DOM。

可信组件自身样式采用独立 CSS 文件；项目使用 CSP nonce 时可通过 cspNonce 传给库创建的受控样式节点。文件样式在清理后改写为 class 与受控 style 节点，不能直接给源 HTML 的任意节点附上可信 nonce。CSP meta 不用于 frame-ancestors，这类指令需要 HTTP 响应头；规则依据 [MDN CSP 说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)。

## 6. 转换运行环境的版本

converter 镜像打包 Python、LibreOffice、Pillow、pydicom 与压缩像素解码插件、XLS/OOXML 解析器、SSF 辅助程序和固定字体。所有支持格式在镜像启动自检中可枚举，完整镜像必须声明 28 种扩展名。

镜像声明 input_contract_version、manifest_schema_version、image_digest、font_digest 和处理器清单。host 在启动及领取任务时确认 profile 对应镜像可用。不能为满足一个旧 profile 临时运行当前 latest 镜像。

浏览器包版本、host 包版本和转换镜像版本可以分别发布，但必须有明确兼容矩阵。改变字体、处理器或展示预算会改变 profile 摘要；兼容 bug 修复同样不能在旧摘要下偷偷替换实际结果。

## 7. 升级与回退

数据库升级文件带序号和摘要，项目发布阶段显式执行。两个并发发布进程通过 schema 升级锁协调；不在每台 API 启动时竞相建表。已有版本脚本不可修改，新字段使用后向兼容方式新增。

升级顺序：准备兼容的 SQL 变更 → 部署能读新旧协议的 host → 部署对应静态资源和组件 → 部署转换镜像 → 登记并启用新 profile。只有转换结果需要新规则时才生成新 profile 结果，用户打开旧文件不会强制重新转换。

回退检查旧 host 是否支持当前 schema 和清单。支持则回退二进制和组件并继续读取旧结果；不支持则拒绝启动，不执行自动删列或回滚数据。发布清单记录可回退范围和正在使用的 profile。

## 8. 包交付验证

| 范围 | 必须确认的行为 |
|---|---|
| NPM 发布内容 | pack 后确实包含 d.ts、CSS、Worker 和资产清单，不包含业务文件、测试密钥或转换临时文件 |
| 前端构建 | React 19 + Vite 的真实消费示例通过；服务端导入无 window 报错；重型引擎按需分包 |
| 页面共存 | 多个组件和项目原有 PDF/Univer 实例互不覆盖样式、Worker 或数据 |
| 生命周期 | 切文件、切租户、退出、卸载可取消请求并释放图片、Canvas、Worker |
| Node 接入 | 使用已有数据库池、已有身份中间件和已有源文件接口完整预览 28 格式 |
| Go 接入 | 使用已有 SQL 连接、标准 HTTP/Gin 挂接，执行同一套协议和格式样本 |
| 数据边界 | schema 升级只改 preview_ 表；清理只删派生前缀；不会删项目原文件 |
| 转换隔离 | 无网络、无业务凭据、超时和资源限制真实生效；错误能返回组件 |
| 完整性 | 与 03 的格式样本逐项比对，partial 及缺失范围在两种后端和组件中一致 |

验证通过后发布同一版本的协议清单、SQL、两种后端消费示例和浏览器截图/自动化结果。npm pack 或 Go 编译通过只说明产物可构建，不能代替实际文件在浏览器中的展示检查。
