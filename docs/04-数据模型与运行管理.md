# 公共库的数据模型与运行管理

更新时间：2026-09-08 16:24 +0800

版本：v2.0 · 公共库设计规范；本章描述后端库必须保证的行为。

## 1. 复用项目的 MySQL

接入项目提供自己的 MySQL 连接。可以在现有实例中建独立数据库，也可以直接在项目数据库中使用 `preview_` 前缀的表。库只管理自己的表，不读取、修改或升级项目业务表。

默认 MySQL 适配器要求 MySQL 8.0 的事务与任务领取能力。数据库并不是前端包的依赖；后端任务管理需要持久化。需要使用其他数据库时，必须实现并验证完整 Store 语义，不能仅替换连接串。

Node 适配器复用项目的 mysql2 Promise Pool，连接管理依据 [mysql2 官方文档](https://sidorares.github.io/node-mysql2/docs)；Go 适配器复用 `*sql.DB`。库取得和归还自己的事务连接，不关闭项目传入的池，不修改项目全局连接参数。API 与后台进程若各建连接池，项目负责在数据库总连接预算内配置两者。

表名前缀仅接受后端配置中的 ASCII 字母、数字和下划线，长度 1–24，不能来自请求参数。SQL 值使用参数绑定；表名通过校验后的固定模板生成。namespace 标识接入项目，tenant_id 标识项目租户，两者都参与记录归属检查。

## 2. 必需的数据表

默认表名如下；前缀可配置，逻辑结构由统一 SQL 定义维护。时间为 UTC，大小为 64 位整数。namespace 最长 64 字符、tenant_id 最长 128 字符、resource_key 最长 256 字符、source_version 最长 128 字符，使用确定的大小写敏感比较；禁止默认不区分大小写的排序规则把两个业务版本合并。浏览器看不到源句柄、对象 key 或运行节点的文件路径。

| 表 | 主要字段 | 关键约束 |
|---|---|---|
| `preview_schema_versions` | version、checksum、applied_at、library_version | version 唯一；脚本摘要不可悄悄改变 |
| `preview_sources` | id、namespace、tenant_id、resource_key、source_version、filename、extension、size_bytes、expected_sha256、verified_sha256、handle_json、status、created_at、invalidated_at | namespace + tenant_id + resource_key + source_version 唯一 |
| `preview_profiles` | id、namespace、digest、schema_version、converter_image_digest、font_digest、config_json、enabled | namespace + id 唯一；digest、配置不可修改 |
| `preview_records` | id、source_id、namespace、tenant_id、profile_id、generation、current_job_id、execution_state、revision、published_result_id、published_revision、cleanup_state、last_error | source_id + profile_id 唯一 |
| `preview_jobs` | id、namespace、tenant_id、kind、operation_id、preview_id、generation、attempt_no、status、stage、progress、available_at、lease_owner、lease_token、lease_expires_at、queued_at、started_at、heartbeat_at、deadline_at、finished_at、actor_user_id、payload_json、error | kind + operation_id + attempt_no 唯一；preview_id + generation、领取与租约索引 |
| `preview_results` | id、preview_id、job_id、published_revision、manifest_key、manifest_sha256、availability、warnings、published_at、retired_at、retain_until、cleanup_state | preview_id + published_revision 唯一；job_id 唯一 |
| `preview_artifacts` | id、result_id、role、media_type、size_bytes、sha256、object_key、storage_kind | result_id 索引；归属从 result → preview → source 校验 |
| `preview_job_events` | id、job_id、sequence、event_type、stage、safe_details、created_at | job_id + sequence 唯一 |
| `preview_idempotency` | namespace、tenant_id、user_id、method、route、key、request_hash、operation_id、status、expires_at | 身份范围 + 方法 + 路由 + key 唯一 |

库不保存项目的登录密码、业务角色副本或浏览器 token。权限实时调用项目函数，清单也不包含用户个人权限。原文件归项目管理，因此库不需要第二套文件上传分片表或项目接入账号表。

source 的 status 为 active / unavailable。active 表示项目提供了可解析的不可变版本，verified_sha256 可在首次读取前为空；发布结果前必须完成实际字节验证。第一次写入 verified_sha256 使用事务条件更新；后续尝试必须匹配，不能覆盖成新摘要。

转换 operation_id 由 preview_id 与 generation 确定；清理 operation_id 为独立清理操作编号。同一清理请求重放复用编号，不同轮次清理不会与已结束的清理任务发生唯一键冲突。

cleanup_state 为 idle / pending / running / failed，用于阻止正在清理的记录同时重新生成。availability 只从 published_result 对应的已校验清单获得，无发布指针即 none，不维护另一套可独立变更的“是否成功”字段。

## 3. Store 的完整能力

库内 Store 提供具备业务原子性的操作，而不是让接入项目自己拼接 CRUD：

| 操作 | 必须保证的事务语义 |
|---|---|
| ensurePreview | 源记录与预览唯一；只对新入口创建一个 queued job |
| claimJob | 转换只领取当前有效轮次；清理领取固定目标集合；均原子写入租约与开始时间 |
| heartbeat | 仅当前执行凭证能延长租约 |
| publishResult | 检查源有效、当前 job、租约、清理状态后同时写结果和发布指针 |
| failOrRetry | 旧任务结束与下一尝试入队、current_job_id 更新不可分离 |
| cancelGeneration | 取消当前轮次并使旧执行凭证失效，不影响已发布结果 |
| invalidateSource | 源失效、所有预览阻断、活动任务取消与清理排队原子完成 |
| clearResults | 阻断该入口的新生成，撤去发布指针并固定待清理结果集合 |

Go 与 Node 使用共同 SQL 模板和协议语义，各自适配事务连接。所有变更固定锁顺序为 source → preview record → job；领取候选可先无锁选择 ID，再按此顺序锁定并重新验证。存在竞争时跳过已被领取项，不凭第一次读取的结果直接写 running。数据库死锁重试整个短事务，且次数有上限。

## 4. 注册源与创建预览

HTTP 入口先从项目上下文取得 principal，再调用 authorize(view)，随后 resolve 指定业务文件版本。校验 namespace、tenant、版本、扩展名、字节数和内部句柄的允许字段；文件名只作为元数据，不能拼入命令或路径。

有同一源版本记录时比对其长度、扩展名和已知摘要；有冲突返回 SOURCE_CHANGED，不能更新旧记录“修复”。需要新建预览时还必须通过 generate 权限，然后事务内插入记录与 queued job。事务提交之后响应 202；响应丢失时重放幂等键取得同一个操作。

预览创建不重复复制原文件。后台通过 SourceProvider.open 读取确定版本，在临时只读输入副本上计算实际 SHA-256。版本、长度或摘要不符时不运行转换器。强版本读取失败而底层只提供最新文件时返回 SOURCE_CHANGED，不能悄悄预览新版本。

原生 PDF 的结果可引用 source 对象，storage_kind=source_reference；其他格式生成 derived 对象。清理 source_reference 仅删除引用记录，不删除项目原文件。原生 PDF 的内容读取仍经过项目权限和指定版本读取适配器。

## 5. 任务领取、进度与恢复

### 5.1 领取

后台管理进程明确配置 worker_id、namespace 和并发槽位。只有本机有空闲转换槽位和磁盘预留空间时才领取。数据库使用短事务和锁定读取协调多个节点；SKIP LOCKED 的队列用途参见 [MySQL 官方说明](https://dev.mysql.com/doc/refman/8.0/en/innodb-locking-reads.html)。

转换任务 kind=convert，每个 job 对应一次尝试。领取后写入随机 lease_token、lease_owner、60 秒有效期、started_at 与 480 秒总截止时间。排队不计入运行耗时，不在等待槽位期间提前标记 running。

同一个 namespace 下有多个租户时轮转领取，单轮每租户最多一个任务；每租户活动任务上限默认 2，可由项目配置。每次领取都检查 source active、cleanup_state idle、generation 和 current_job_id 仍匹配。

### 5.2 心跳与阶段

每 10 秒续租，条件包括 job_id、status=running、lease_owner、lease_token。数据库失联达到租约到期，管理进程终止容器并放弃发布。处理结束时不因为“已经算完”跳过有效执行凭证检查。

阶段为 queued、fetching、inspecting、converting、validating、publishing。只有实际总量已知时返回 progress={done,total,unit}；其他情况为 null。进度实质变化每秒最多持久化一次并递增 revision，纯心跳不增加页面状态版本。

### 5.3 重试

同一 generation 最多 3 次尝试，自动重试仅用于存储短暂失败、节点意外退出等基础设施问题，退避为 5 秒、30 秒加随机偏移。损坏、密码、资源超额、确定性转换失败和转换超时默认不自动重试。

人工 retry 新建 generation，attempt_no 从 1 开始。活动任务存在时返回 ALREADY_RUNNING；清理进行时返回 CLEAR_IN_PROGRESS。自动重试和人工重试都生成新 job ID 和输出目录。

恢复扫描每 15 秒寻找过期租约，事务内复核后结束旧 job，并按规则创建新尝试。原节点恢复后既不能续租，也不能覆盖当前状态。后台启动时查询遗留容器的 job 与租约，终止失效容器，再清理其本地目录。

## 6. 发布结果

1. 转换容器结束，管理进程检查候选清单协议和主结果是否有效。
2. 检查相对路径、禁止软链接及目录穿越，核实每个产物大小、摘要、MIME 和引用。
3. 按格式验证 PDF、图片、表格块和 HTML；不把进程退出码 0 等同于展示成功。
4. 为产物分配 ID，把不可变结果上传到本 job 的私有派生目录，验证实际存储完成。
5. 再次查询 SourceProvider.isAvailable，确认业务源仍可用；开启发布事务并检查 source active、generation、current_job_id、有效租约、cleanup_state idle。
6. 同时插入 result/artifact、移动发布指针、递增 published_revision 和 revision、将 job 与生成状态设为 succeeded。
7. 提交后才对外可见，旧结果记为 retired 并进入保留期。

原文件删除与库内发布之间不存在跨系统自动事务，因此访问接口始终再次执行项目权限与源有效性检查；失效通知负责将库状态最终同步并清理。不能因转换完成就绕过项目已经生效的删除或权限变更。

旧任务即使上传成功，也不能通过步骤 5；其未发布对象由清理器回收。新结果按发布版本整体切换，组件固定 manifest 的 published_revision，不把旧目录索引与新分块混用。

## 7. 文件存储与垃圾清理

对象 key 由库生成，例如：

```text
{configured-prefix}/{namespace}/{tenant-storage-id}/previews/{preview_id}/jobs/{job_id}/artifacts/{artifact_id}
{configured-prefix}/{namespace}/{tenant-storage-id}/previews/{preview_id}/jobs/{job_id}/manifest.json
```

tenant-storage-id 是服务端生成或编码后的路径安全值，不直接拼任意租户显示名。对象仅私有读写，浏览器通过项目接口取得内容。put 核对大小和 SHA-256，不能把多段上传 ETag 当作内容摘要。

删除结果先在事务内令 cleanup_state=pending、取消当前生成、清空发布指针，并把现存结果标记待清理。清理任务 kind=cleanup，由轻量管理循环执行，不占用文件转换容器；使用同样的租约与续租机制，但按自己的目标集合和 cleanup_state 领取；目标集合记录在任务负载中，不能简单删除整个预览前缀而误删未来的新结果。

确认旧有效执行者已失效、目标派生对象已删除后 cleanup_state=idle。待清理结果从事务标记起即返回 RESULT_EXPIRED，不因对象还在存储中就继续提供。预览保持 cancelled/none，允许后续显式 retry。清理失败保留 failed 状态及错误，按 1 分钟、5 分钟、30 分钟、最长 6 小时持续退避；清理不受转换任务每轮最多 3 次的限制。超过 30 分钟向项目监控告警。

| 内容 | 保留规则 |
|---|---|
| 原文件及其不可变副本 | 项目负责，库永不通过派生清理器删除 |
| 当前发布结果 | 默认保留，直到项目清理或源失效 |
| 已被新结果替换的版本 | 保留至少 8 小时；项目可调，源失效时立即禁止读取 |
| 未发布产物与失败临时文件 | 24 小时后回收，先检查任务租约及引用 |
| 成功任务本地目录 | 发布后立即释放 |
| 幂等记录 | 24 小时 |
| 任务与无正文诊断事件 | 默认 30 天 |

清理器先标记候选，下一轮再次检查任务和发布引用后删除。有效任务目录不因超过某个创建时间就被清掉。数据库引用和对象状态矛盾时停止相关读取并报告完整性错误。

## 8. 处理运行环境

Go 与 Node 后端调用同一种转换镜像，容器内采用 Python 处理文件，LibreOffice 生成 PDF，Node 辅助程序批量处理表格显示格式。Node 宿主项目不需要通过 NPM 安装 LibreOffice；这些系统依赖存在转换镜像里。

容器以非 root 运行，根目录只读，无网络，不挂载项目业务目录、数据库凭据、存储密钥或容器管理 socket。只读输入目录和可写输出目录按 job 隔离；调用进程拿到结果后自行上传，不把 OSS 凭据注入转换器。

| 初始参数 | 默认值 |
|---|---|
| 单后台进程转换槽位 | 2 |
| 单租户活动转换数 | 2 |
| 单转换容器 | 2 CPU、4 GiB 内存、128 PID |
| 输入源副本 | 最大 4 GiB，开始领取前预留空间 |
| 临时和输出卷 | 8 GiB，其中新增产物最大 2 GiB |
| 总运行时限 | 480 秒，包括读取、转换、验证、上传 |
| Office 子进程时限 | 单次 180 秒，不在同一任务内无界重启 |
| 每任务诊断日志 | 最大 1 MiB，超出保留截断标记 |
| Office 压缩包解析预算 | 展开 4 GiB、50000 文件、目录深度 32 |
| JSON/XML 结构嵌套 | 最大 256 层，超出转安全源文本或报限制 |

容器硬限制导致退出时返回 RESOURCE_LIMIT_EXCEEDED；处理器正常达到展示预算并产出可读部分时可以发布 partial。两者不能都叫成功。磁盘不足不领取新任务，已领取任务终止时释放自己的预留。

标准 Runner 通过项目受限的容器执行通道创建任务；Kubernetes 使用固定 Pod 模板和专用权限，Docker 环境的执行权限只交给项目后台管理进程。转换子容器不得继承执行通道的权限。节点间共享输入输出必须有明确的卷调度安排，不假定本地目录天然跨节点可见。

## 9. 请求、权限和缓存

接口依次执行：项目身份检查 → 资源归属查询 → authorize → 源有效性 → 发布版本和产物归属 → 条件请求/Range → 内容读取。任何缓存命中都不能绕过权限。请求参数不能指定本地路径、对象 key、SQL 前缀或执行命令。

库不缓存“用户有权限”的允许访问的判定。长传输每秒重复检查，项目回调应验证其登录上下文和当前业务权限；失败中止流。项目可在自己的权限系统内部优化查询，但应明确其撤权生效语义。

已生成字节可以放在后端有界缓存中，单 API 实例默认 64 MiB，键含 result_id、artifact_id 和摘要。前端缓存还包含 identityKey 和文件版本；退出、切租户、文件失效时立即清空。动态响应 no-store，静态带版本资源长期缓存。

分页表格接口根据固定发布版本、行列范围查找相交块，最多返回 200 行 × 100 列。一次请求最多读取 32 MiB 未压缩数据，超过返回 WINDOW_READ_LIMIT，组件缩小窗口。返回 cells、真实 range、merges、coverage、warnings，合并区域保留原坐标并提供窗口内裁剪坐标。

## 10. 项目接入的运行接口

库输出结构化日志回调和指标回调，项目决定使用哪套日志、监控和告警工具，不安装另一套可观测平台。日志字段为 request_id、namespace、preview_id、job_id、stage、duration、error_code；不记录 Cookie、Authorization、原文件正文、患者标签或 source handle。

readiness 检查 schema、存储可用性、profile 与镜像摘要匹配；后台 readiness 还检查空间、转换运行器和格式解码样本。API 正常不代表后台转换器就绪，二者分别报告。

监控记录排队时长、分阶段耗时、失败和 partial 比例、租约过期、迟到发布被拒绝、资源超限、清理积压、组件首屏和内容读取错误。初始告警为最老排队超过 60 秒持续 5 分钟、清理超过 30 分钟、任何摘要不一致。

## 11. 两种后端的行为验收

Go 和 Node 使用同一套样本验证：同文件并发创建只产生一个入口；同一任务多节点只能有一个有效执行者；失联重试可恢复；旧任务不能覆盖新结果；清理与发布竞争不会复活结果；租户互读返回 404；源版本变化拒绝发布；原文件删除事件重放幂等；项目权限变化对每个内容接口生效。

生命周期验收还包含：库不会关闭项目数据库连接、不会自行修改业务表、不会删除原文件；包导入不启动网络监听或后台扫描；进程关闭能够停止领取并终止超时转换；同一版本两种实现产生兼容的清单、错误码和状态对象。
