# 格式处理与查看器设计

更新时间：2026-09-08 16:24 +0800

版本：v2.0 · 公共库设计规范；格式处理由统一转换运行环境实现。

## 1. 处理器的统一约定

一个任务只处理一份不可变源文件。任务管理进程在隔离容器启动前准备好源文件、只读配置和独立输出目录。处理器只允许写本次输出目录，不直接访问项目业务接口，不下载外部资源，不启动文件中的宏或代码。

处理器入口接受下列输入文件，命令行只传 `--request /input/request.json`，避免把文件内容或用户文件名拼入命令：

```json
{
  "contract_version":"1.0",
  "job_id":"job_01",
  "source":{"path":"/input/source.xlsx","extension":"xlsx","size_bytes":183200,"sha256":"<sha256>"},
  "profile":{"id":"standard-v1","digest":"<不可变配置摘要>"},
  "output_dir":"/output",
  "limits":{"wall_time_seconds":480,"output_bytes":2147483648}
}
```

退出码 0 表示处理器已写出候选结果，仍需任务管理进程验证后才能发布。非零表示没有可发布的主结果；错误写到 `result.json` 的结构化错误字段。stdout 仅写一条结果定位 JSON，stderr 写有界诊断，不输出文件正文或机密元数据。

处理器先写临时文件，关闭句柄后改名为最终文件，再写 `result.json`。每个文件声明相对路径、MIME、字节数和 SHA-256。管理进程重新计算并验证；拒绝绝对路径、`..`、软链接和目录外引用。文档内嵌文件不提取为可执行附件供浏览器打开。

## 2. 结果清单

### 2.1 公开清单结构

内部候选清单使用相对路径；公开清单使用分配后的 `artifact_id`，路径不出现在浏览器响应中。

```json
{
  "schema_version":"1.0",
  "preview_id":"prv_01",
  "source_id":"src_01",
  "profile_id":"standard-v1",
  "published_revision":1,
  "source":{"name":"季度报告.xlsx","extension":"xlsx","size_bytes":183200},
  "default_representation_id":"rep_table",
  "availability":"partial",
  "representations":[
    {
      "id":"rep_table",
      "kind":"table",
      "label":"表格",
      "status":"ready",
      "completeness":"partial",
      "affects_completeness":true,
      "entry_artifact_id":"art_workbook",
      "coverage":{"unit":"rows","shown":200000,"total":260000,"scope":"sheet_1"},
      "warnings":[{"code":"ROW_LIMIT_REACHED","message":"工作表 A 展示前 200000 行","scope":"sheet_1"}],
      "error":null
    },
    {
      "id":"rep_pdf",
      "kind":"pdf",
      "label":"打印版",
      "status":"failed",
      "completeness":"unknown",
      "affects_completeness":true,
      "entry_artifact_id":null,
      "coverage":null,
      "warnings":[],
      "error":{"code":"CONVERSION_TIMEOUT","message":"打印版生成超时","retryable":true}
    }
  ],
  "artifacts":[
    {"artifact_id":"art_workbook","media_type":"application/json","size_bytes":2048,"sha256":"<sha256>","role":"entry"}
  ],
  "capabilities":{"search_scope":"current_sheet","static_only":true},
  "warnings":[{"code":"PARTIAL_CONTENT","message":"部分内容可预览，详情见各展示方式"}]
}
```

示例省略其余数据块产物，实际清单或其受校验的索引必须能找到每一个引用。服务不能仅验证入口 JSON 存在就发布。公开清单的 `source` 不包含 DICOM 患者信息、源文件路径或对象存储地址。

### 2.2 通用字段规则

| 字段 | 规则 |
|---|---|
| `schema_version` | 主版本不兼容必须新建，次版本仅新增可选字段；查看器对不支持的主版本显示升级提示 |
| `representations` | 同一文件可有多个展示方式；按明确优先级选择默认结果，不由浏览器按扩展名猜 |
| `status` | `ready / failed / skipped`；ready 必须引用存在、可读且结构有效的主入口；源内容合法为空时允许空内容 |
| `completeness` | `complete / partial / unknown`；不能验证完整时使用 unknown，并使整体 availability 为 partial |
| `affects_completeness` | 原计划输出缺失或降级为 true；不适用的附加输出 skipped 为 false |
| `coverage` | 以行、帧、单元格或字符说明展示范围；总量未知时 total 为 null；多工作表的明细放工作表索引 |
| `warnings` | 稳定 code + 中文 message + 可选 scope；不使用纯日志承载用户需要知道的缺失 |
| `capabilities` | 明确搜索作用范围、是否静态、是否有文字层等；权限由项目 authorize 回调决定，不写进共享清单 |
| `artifact_id` | 不透明编号；服务检查它与该发布版本的关联，不能按字符串拼出对象路径 |

正常的零行工作表是有效空内容；“未解析到任何结果”不是空工作表。空白 PDF 页面同样有效，不能以文字量为零判断 PDF 转换失败。

## 3. PDF、Word、RTF 与幻灯片

### 3.1 PDF

原生 PDF 不重新排版。源引用由后端库绑定当前 source_id，候选清单只能声明 source_reference 类型，不能提供输入目录外的路径。任务检查头部、可打开性、是否加密、页数及基本结构，通过后把原文件登记为只读 PDF 产物引用，生命周期仍跟随该文件。加密文件返回 `PASSWORD_REQUIRED`；服务不接收或保存密码。

使用自托管 PDF.js 展示。查看器提供页码输入、上一页/下一页、适合宽度、适合页面、缩放、文字选择与已有文字搜索。缩略图按需生成或在浏览器按页生成；不在首次打开时渲染整个文档。页面离开可见区后释放 Canvas 和渲染任务，保留有限的邻近页缓存。

PDF.js 的网络适配层统一处理项目认证、单区间读取和取消；登录续期由项目请求层处理。若关闭自动预取，应同时按库要求关闭流式预取；不能只设置一个选项就认定已按需加载。读取适配参数依据 [PDF.js 官方 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html)。

不启用 PDF JavaScript、提交表单、启动外部程序、打开嵌入附件或自动外链导航。只展示表单已保存的外观。外链由查看器统一拦截，提示目标域名后由业务页面决定是否打开。没有文字层的扫描 PDF 仍能阅读，搜索提示“此文件没有可搜索文字”，不假装执行 OCR。

### 3.2 DOC、DOCX、RTF、PPT、PPTX

LibreOffice headless 把源文件导出为 PDF。每次转换使用独立用户配置目录和工作目录，禁止共享进程的用户配置锁。进程以参数数组启动，文件名不能形成 shell 命令。宏执行级别设为禁用，外部链接更新禁用，整个容器无外网。

转换步骤：检查格式 → 判断加密及损坏 → 运行导出 → 验证 PDF 可打开、页数和文件长度 → 记录字体替换及转换告警 → 发布 PDF。进程退出码为 0 但没有有效 PDF 时返回 `INVALID_CONVERSION_OUTPUT`。

字体包固定随镜像发布，包含明确授权可分发的中文和拉丁字体及替代映射。检测到缺失字体时记录 `FONT_SUBSTITUTED` 和字体名；字体变化会改变处理规则摘要，不能沿用旧缓存。

幻灯片展示静态页面。动画、视频播放、演讲者操作不执行；检测到这类内容时说明仅展示静态页面。文档编辑、协同、修改表单和批注写回不属于查看器行为。已有批注的显示按导出配置固定：正文视图不追加批注页，清单声明该能力范围。

## 4. XLS、XLSX、XLSM

### 4.1 处理步骤

1. 判断 XLS 二进制容器或 XLSX/XLSM 压缩容器；检查工作簿结构、解压体积和文件数限制。
2. 读取工作表列表、名称、显示顺序、隐藏属性、有效行列范围、合并区域、列宽、行高、冻结区。
3. 读取单元格原始值、类型、公式、文件已保存的公式结果、样式和数字格式。
4. 结合工作簿日期系统生成展示字符串，保留原值与来源，避免显示值反过来污染原值。
5. 生成样式去重表、工作表索引和有字节上限的行数据块；稀疏单元格保持稀疏，不扩成巨大二维数组。
6. 检测图片、形状和图表；满足本节条件时额外导出静态 PDF；XLS 无法可靠识别嵌入对象时按第 4.6 节规则处理。
7. 校验行列引用、合并区域、分块覆盖范围和所有产物，发布表格结果。

XLS 用 [xlrd](https://xlrd.readthedocs.io/en/latest/) 适配器读取数值和基础格式；它不提供公式源码、图表或图片对象，相关能力标记 unknown，不能声称已完整提取。XLSX/XLSM 用 [openpyxl](https://openpyxl.readthedocs.io/en/stable/api/openpyxl.reader.excel.html) 读取与只读 OOXML 元数据补充，分别取得公式和缓存值。不使用 XLS 解析器处理 XLSX，不通过一个统一字符串转换丢弃类型信息。工作簿里的 VBA 保留在原文件中但不加载、不执行。

### 4.2 单元格数据约定

坐标统一从 1 开始。查看器库内部的从 0 开始坐标由适配层转换，协议和审计定位仍使用原坐标。

```json
{
  "row":8,"col":3,
  "type":"number",
  "raw_value":"45292",
  "number_format":"yyyy-mm-dd",
  "display_value":"2024-01-01",
  "formula":null,
  "cached_value":null,
  "value_source":"literal",
  "style_id":"style_12",
  "warning_codes":[]
}
```

| 字段 | 规则 |
|---|---|
| `type` | `string / number / boolean / date / error / blank`；空白与数字 0、空字符串区分 |
| `raw_value` | 保留源语义，数字用十进制字符串，避免 JSON 数字再次损失精度；如果源解析已损失则不能声称可恢复 |
| `display_value` | 转换阶段确定的只读展示字符串，不由浏览器重新计算业务值 |
| `formula` | 原公式；在能取得公式的格式中，共享公式按所在单元格解析相对引用；解析不了时保留原始公式标识并警告；XLS 为 null 并标记未提取 |
| `cached_value` | 文件保存时的结果；不存在与空结果分别记录 |
| `value_source` | `literal / saved_formula_cache / formula_without_cache / unknown` |
| `style_id` | 引用去重后的字体、填充、边框、对齐及数字格式；仅允许固定字段 |

### 4.3 公式和日期

优先展示文件已经保存的公式结果，不自动连接外部工作簿、不从浏览器或服务执行公式重算。缓存缺失时显示“未保存计算结果”，单元格详情中展示公式；该单元格仍计入有效行列，不得被当成空白删除。缓存可能不是最新值时，页面说明“公式值为文件保存时的结果”。

日期遵守工作簿的 1900 或 1904 日期系统。1900 系统中的序号 60按 Excel 的历史日期语义展示并标注，不用普通日期库悄悄改成另一日期。日期与时间值不隐式按服务器时区偏移。明确的文本日期保持文本，不自行猜测转换。

数字格式由统一适配器处理，不自行用几个正则替代 Excel 格式。采用 SheetJS 的 SSF 格式化能力作为 Node 批处理辅助程序：一次任务批量传递格式和值，返回字符串；不为每个单元格启动进程。保留原值、格式和显示值的分离，与 [SheetJS 格式字段说明](https://docs.sheetjs.com/docs/csf/features/nf/)一致。

必须覆盖百分比、货币、千分位、小数、科学计数、分数、补零、日期时间、负数与自定义单位。对于超出辅助库数值精度或不支持的格式，显示保留精度的原始十进制字符串并提示 `FORMAT_FALLBACK`，不能输出看似正常但改变数值的结果。格式化程序自身也运行在同一隔离容器中。

### 4.4 工作表与分块

工作簿入口包含 `sheets[]`、`styles_artifact_id` 和读取能力。每个工作表包含 `sheet_id,name,order,visibility,row_count,col_count,shown_row_end,shown_col_end,merges,freeze,coverage,chunks[]`。`visibility` 为 visible/hidden/very_hidden；默认仅打开可见表，隐藏表在明确标注的列表中由用户选择。隐藏属性不当作权限隔离；项目查看授权单位是整个文件。

每个块最多 1000 行且不超过 4 MiB 未压缩 JSON；达到任一条件就切块。若单行超限，再按列区间切块。索引记录 `row_start,row_end,col_start,col_end,artifact_id,size_bytes`，块范围不重叠，缺失的稀疏单元格解释为空白。超长单元格单独截断并记录原始字符数，不让一个值突破产物限制。

保留具有内容、公式、批注提示或展示所需样式的单元格。只因为远端存在空白样式不能扩展有效数据到整张 Excel 最大网格。合并区域跨分块时在工作表元数据中保存一次，不复制大量空白格。

### 4.5 两种表格页面模式

小表使用 Univer 的只读表格展示能力，适配器把确定的显示值和基础样式送入网格。XLSX/XLSM 的公式作为单元格详情展示，不能传给公式执行模块导致自动重算；XLS 标注“此格式未提取公式源码”。不开启编辑、写回或远程导入接口。本设计只使用其开源展示能力；[Univer 官方能力划分](https://docs.univer.ai/guides/pro)中的额外导入、服务能力不视为已具备。

当展示范围的行数 × 列数不超过 200000 且数据总量不超过 16 MiB 时，使用小表模式。超出任一阈值使用分页大表模式：每页最多 200 行 × 100 列，可跳到指定行列、移动列区间、切换工作表。界面始终显示原工作表真实行号和列名，例如“第 2001–2200 行，A–CV 列”。大表不先把整张工作簿装入浏览器。

大表使用只读窗口表格组件，固定表头和按窗口裁剪的合并区域。合并单元格起点在窗口外时从元数据补回显示值，并标注完整合并范围；不得把窗口内第一格误认成原始起点。最多保留当前页与相邻两页的数据，离开工作表释放数据缓存与请求。

所有表格共享查看器级最多 4 个并行数据请求。切表和切页使用 AbortController 取消无关请求；迟到响应必须核对发布版本、工作表和窗口请求编号后才能写入页面。小表搜索覆盖当前工作表已加载内容；大表搜索只覆盖当前窗口，界面明确写“在当前窗口查找”。服务不对未扫描数据宣称全表搜索结果。

单元格详情展示原始值、显示值、公式、缓存来源及告警。复制操作按用户当前选择复制显示值；需要原始值时使用详情中的独立操作。复制到表格应用可能被解释为公式的字符串，提供纯文本复制并进行公式前缀防护，不执行原内容。

### 4.6 附加 PDF

文件不超过 30 MiB、存在可展示嵌入对象且符合以下规则时计划生成附加 PDF：仅图片或形状时最大有效行号不超过 5000；含图表时最大有效行号不超过 50000。超范围记 `skipped`，告警说明表格模式不展示这些对象；若对象是源内容的一部分，其缺失仍使表格完整性为 partial。

XLS 因主解析器不提供完整对象信息，只要文件不超过 30 MiB、最大有效行号不超过 5000，就计划生成附加 PDF；超出条件时记录 `EMBEDDED_CONTENT_UNKNOWN`，不声称图片或图表不存在。

打印版使用固定 LibreOffice 导出配置，不修改源文件的公式缓存。由于导出引擎可能重新计算公式，清单和页面注明“打印版可能由转换引擎重新计算，表格视图展示文件保存值”；二者值不一致不能自动覆盖表格视图。附加 PDF 不作为表格数值的权威来源。

## 5. CSV

使用 Python `csv` 的流式解析能力，输入文本流保留换行，由解析器识别带引号的跨行字段，不先按换行字符串拆分记录。探测 UTF-8/BOM、UTF-16，必要时按受限候选编码尝试；不能确定时使用替换字符并标记 `ENCODING_UNCERTAIN`。

分隔符在逗号、制表符、分号中通过有界样本检测；检测不稳定时按逗号处理并提示。原文件没有表头标记，第一行始终作为数据展示，不自动吃掉第一行。用户界面可以临时“将首行固定显示”，但不改变保存数据。

所有字段默认字符串：`00123` 保留前导零，长编号不转浮点数，`=SUM(...)` 作为文本显示。列数不一致按实际最大列补空白，记录异常行，不把多余列丢掉。输出使用与电子表格一致的工作表协议和分页查看器。

## 6. 图片与多帧文件

PNG/JPG/JPEG/BMP/WEBP/TIF/TIFF 使用 Pillow 按帧读取。先检查像素维度和帧信息，再解码当前帧，不先把所有帧装入内存。校验真实解码能力，遇到不支持的压缩方式返回明确错误。

应用 EXIF 朝向，把颜色转换为浏览器可显示的 sRGB；有 ICC 信息时按受控色彩管理转换。透明通道保留。输出长边最大 2600 像素；缩略图长边 320 像素。存在透明度或细线内容时采用 PNG 或无损 WebP，普通照片允许固定质量 WebP。原图不被替换或覆盖。

多帧图像最多输出 200 帧。对依赖前序帧的动画按顺序合成正确的静态帧，不能把差分帧当完整图。超过限制时记录实际输出范围；总帧数无法安全获知时 total 为 null。图册仅提供静态切帧，不默认循环播放。

帧目录包含 `frame_id,source_frame_number,width,height,thumbnail_artifact_id,image_artifact_id,source_dimensions,transforms`。查看器展示当前帧、相邻帧和缩略图列表，提供适合窗口、原展示尺寸、缩放、旋转、上一帧、下一帧。显示旋转仅作用于当前浏览器视图，不写回源文件。

## 7. DCM 与 DICOM

DCM/DICOM 通过 pydicom 读取。检查像素数据是否存在、传输语法、帧数、像素维度、位深和颜色解释。无像素数据的合法 DICOM 文件展示受控基本信息文本作为主结果，清单说明没有图像；不是直接判成“损坏图片”。

存在像素数据时逐帧解码，采用 [pydicom iter_pixels](https://pydicom.github.io/pydicom/stable/reference/generated/pydicom.pixels.iter_pixels.html) 的逐帧入口，避免在输出帧数上限前就分配完整三维像素数组。镜像内安装并登记 JPEG、JPEG-LS、JPEG 2000 和 RLE 所需的受支持解码插件；启动自检使用实际样本检查插件可用性。未能解码某种传输语法时返回 `IMAGE_CODEC_UNSUPPORTED`，附传输语法 UID，不返回患者标签。

灰度处理顺序：解析有符号像素和有效位深 → 应用 Modality LUT 或 Rescale Slope/Intercept → 应用 VOI LUT 或 Window Center/Width → 根据 MONOCHROME1 反相 → 映射到浏览器显示灰度。多个窗设置取第一个并记录所选值；无窗信息时按有效像素范围建立显示窗并标记 `WINDOW_DERIVED`。彩色像素按 Photometric Interpretation 做 RGB/调色板转换，不套用灰度窗口。

源像素不会直接截取低 8 位。静态显示结果可以映射为 8 位 PNG，但必须保留原位深、窗设置和变换说明。采用无损输出，不能把有损压缩伪影当成原始信息。像素处理语义参照 [pydicom 像素数据说明](https://pydicom.github.io/pydicom/stable/guides/user/working_with_pixel_data.html)。

查看器提供静态帧切换、缩放和显示参数说明，不提供实时调窗、测量、序列配准或三维重建。最多输出 200 帧。图像内已经烧录的个人信息不会因隐藏标签而消失；服务不会把该处理称为脱敏。公开元数据只包含 SOP 类型、传输语法、图像尺寸、帧数及显示参数；患者姓名、ID、日期等标签不进清单或日志。

## 8. HTML、HTM、XHTML

### 8.1 生成静态页面

解析为文档树后按允许列表重建输出，禁止正则替换充当 HTML 清理器。保留段落、标题、列表、表格、常见文本样式和内嵌图片；移除 script、iframe、object、embed、form、input、按钮事件、meta refresh、base、外部样式和网络资源引用。

元素移除要保留其后的正常文本。例如 `甲<script>...</script>乙` 必须留下“甲乙”，不能把尾部“乙”一起丢失。注释、无效标签和重复属性由解析器规范化；XHTML 按安全 XML 规则禁止外部实体后再转换。

CSS 使用 [tinycss2](https://doc.courtbouillon.org/tinycss2/stable/) 解析后按属性和属性值允许列表重建。它只负责语法解析，允许哪些属性和值由公共库实现的清理规则决定。只保留布局与基础视觉属性。去除 `@import`、所有外部 `url()`、自定义属性中隐藏的 URL、浏览器特有可执行表达式。图片只接受经过独立解码和大小检查的 data PNG/JPEG/WebP；不直接接受 SVG 或用户 CSS 作为可信资源。外部图片显示占位说明；单个 HTML 文件不自动读取项目存储中的其他文件。

HTTP(S) 超链接转成可读地址文本，取消主动跳转；保留文档内部锚点。删除的脚本不执行，表单不提交。清单记录移除外部资源、表单和交互逻辑导致的展示范围说明。

### 8.2 浏览器隔离

FilePreview 是项目页面中的 React 组件，HTML 内容进入组件单独创建的 iframe。iframe 使用 `sandbox=""`，不授予脚本、同源、弹窗、表单、下载或顶层导航。它不直接加载项目原始文件 URL。

组件通过项目请求客户端取得经过后端清理的 HTML 产物，验证受控结构后构造 srcdoc。HTTP 产物接口返回 `Content-Type: text/plain; charset=utf-8`、`X-Content-Type-Options: nosniff` 和 `Cache-Control: no-store`，直接打开该接口也不会执行 HTML。

库在 srcdoc 的 head 最前部插入以下固定 CSP meta，再追加清理后的文档内容；文件原有的 meta、base 和策略字段全部移除。

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'none'; script-src 'none'; connect-src 'none'; img-src data:; style-src 'unsafe-inline'; font-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'">
```

这个规则只作用于受限文件页面，不要求项目全站启用 unsafe-inline。宿主 CSP 的限制仍然生效；需要 nonce 时由项目通过组件 cspNonce 提供，只用于库创建的受控样式节点。清理器把允许的 style 属性转成 class 和受控 CSS，禁止把可信 nonce 直接加到文件原有样式节点。

如果宿主策略仍禁止这些样式，保留可读结构并显示 STYLE_BLOCKED_BY_HOST 提示，不能为恢复排版取消沙箱。此时是浏览器环境导致的显示告警，与转换清单中的内容完整性分开记录。

不在 meta 中配置 frame-ancestors 或 sandbox；sandbox 由 iframe 属性保证。srcdoc 的隔离行为依据 [MDN iframe 说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)，策略配置参见 [MDN CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)。iframe 不运行脚本，采用容器高度与滚动，不要求文件内容主动回报高度。

## 9. TXT、MD、JSON、XML、XBRL

TXT 与 MD 按文本展示，保留换行和空白，不把 MD 中的 HTML 渲染进页面。统一输出 UTF-8 并记录检测编码、替换字符和截断位置。页面提供行号、换行开关、块内查找和复制；查找范围明确显示“当前已加载文本”。

JSON 在可控输入规模内验证语法并格式化，重复键不得因转成普通字典而悄悄消失，数字原文保留精度。大文件使用保留 token 的流式显示，不为格式化读入整个文件。语法错误时仍可以源文本阅读，同时显示错误位置；不把“格式化失败”变成看不到任何内容。

XML/XBRL 使用安全解析器，显式禁止 DTD、实体声明、外部引用和网络访问。不能只扫描文件头几 KiB 来判断是否安全。[defusedxml 官方说明](https://pypi.org/project/defusedxml/)提供相关防护参数依据。输入超出树解析预算时展示转义后的源文本，不再尝试建立完整树；源文本模式也绝不交给浏览器按 XML/HTML 执行。

XBRL 按结构化源文本展示，不执行 taxonomy 下载、计算链接或财务报表合成。代码查看器的语法高亮只生成受控 span，不直接插入原始标签。

文本按完整 Unicode 字符边界分块，每块最多 256 KiB，累计展示最多 10 MiB UTF-8；块索引包含起始行、行内偏移及字符偏移，超长单行允许跨块。达到上限时标记 partial，总长度未知则明确未知。每行用于显示的内容还受长行预算约束，但被折叠内容必须与实际被截断内容分别提示。

## 10. IPYNB

使用安全 JSON 读取 Notebook，不运行内核，不安装依赖，不执行代码或调用输出中的脚本。依次提取 Markdown、代码和 raw 单元格，保留单元格编号、执行序号以及源代码。Markdown 以文本展示。

输出仅展示已保存的文本流、错误摘要和 `text/plain` 数据。ANSI 控制序列清理后作为文本显示。HTML、JavaScript、交互 widget 和二进制富输出不执行、不直接渲染；存在时显示“此单元格含未展示的富输出”，记录 `RICH_OUTPUT_OMITTED`。Notebook 有多个输出时分别保留顺序和类型。

最多展示 500 个单元格，每个输出最多 2000 个 Unicode 字符，单元格源代码每个最多 100000 字符，总可展示文本最多 10 MiB。达到任一上限，记录具体单元格及已展示范围。入口和输出块仍受一般产物大小限制。

查看器按单元格分页或虚拟列表显示，默认加载前 20 个，再按需继续；提供跳转单元格、展开/收起输出、代码复制。没有已保存输出的代码单元格显示“文件未保存运行输出”，不能触发后台执行来补齐。

## 11. 默认内容预算与页面约定

下列为 `standard-v1` 的初始配置。修改影响结果的参数必须生成新的 profile 摘要，不能在同一个版本下静默改变。项目上传限制与公共库展示预算分开；库检查源大小，不接管项目上传流程。

| 项目 | 默认值 | 到达限制后的行为 |
|---|---|---|
| 库接受的原文件版本 | 最大 4 GiB | 创建预览返回 SOURCE_TOO_LARGE，不影响项目原文件 |
| 单表行范围 | 200000 行 | 截断后发布 partial，记录范围 |
| 单表列范围 | 16384 列 | 超出范围截断并提示 |
| 工作簿处理单元格 | 累计 2000000 个有效格 | 按表顺序和行列顺序停止，保留已完成范围 |
| 工作表数量 | 200 | 保留前 200 张，记录省略表数 |
| 单元格文本 | 100000 字符 | 截断该格并标注 |
| 图片/DICOM 帧 | 200 | 发布已处理帧并标注 |
| 单帧解码像素 | 100000000 像素，同时受内存硬限制约束 | 解码前拒绝过大帧；其他帧仍可用则 partial |
| 图像显示尺寸 | 长边 2600；缩略图 320 | 记录缩放变换，不标为丢帧 |
| 文本累计展示 | 10 MiB UTF-8 | 在字符边界截断并说明 |
| JSON/XML 整树格式化输入 | 16 MiB | 更大输入走安全源文本分块 |
| HTML 文档树输入 | 16 MiB | 超出时展示转义后的源文本并标记 HTML_TEXT_FALLBACK |
| Notebook | 500 单元格；每输出 2000 字符 | 精确说明截断范围 |
| 表格数据块 | 1000 行且 4 MiB | 分行或分列切块，不靠加大内存解决 |
| 单任务新生成产物 | 2 GiB，不含原生 PDF 的源对象引用 | 处理器能有序收尾则 partial；容器中断且结果不完整则失败 |

“支持格式”与“完整保留所有 Office 动态能力”是不同描述。清单必须精确表达本次实际展示内容；对不支持的嵌入对象、格式替代、行帧截断和富输出省略，页面与接口保持一致。

## 12. 格式验收样本

每个扩展名至少有可读、损坏、类型不符三个基础样本；另覆盖以下语义样本。断言应比较实际显示值和产物可读性，而不是仅检查进程退出码。

| 格式 | 必须验证的内容 |
|---|---|
| PDF/Office | 中文字体、扫描页、已有文字搜索、加密文件、长文档、多页导出、外链和宏不执行 |
| XLS/XLSX/XLSM | 1900/1904 日期、序号 60、无缓存公式、共享公式、长数字、补零、分数、单位、隐藏表、跨窗口合并、大表跳转、内嵌对象提示 |
| CSV | 引号内换行、中文编码、混合列数、前导零、公式开头文本、长编号 |
| 图片 | EXIF 旋转、透明图、CMYK、16 位 TIFF、多帧差分、大尺寸解码、超过 200 帧 |
| DICOM | 有符号 16 位、MONOCHROME1、Modality/VOI LUT、多窗口、无像素、压缩语法、多帧限制、患者标签不出现在响应和日志 |
| HTML/XHTML | script 尾部文本、事件属性、CSS URL、表单、base、外部图片、SVG、嵌套 iframe、DTD/实体攻击 |
| JSON/XML/XBRL | 数字精度、重复键、实体声明位于文件后部、深嵌套、大文件安全源文本、畸形语法仍可读 |
| IPYNB/TXT/MD | 长输出、富输出省略、单元格排序、编码失败、超长行、多字节截断边界、源代码不执行 |
